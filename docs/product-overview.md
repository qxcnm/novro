# 产品概述

## 1. 产品定位

Novro 是面向国内企业团队的轻量级大模型统一接入平台。企业只需要保存一套 API 地址和一套 API Key，就可以通过统一格式调用 Kimi、GLM、DeepSeek 等模型。

Novro 的产品方向不是做复杂的模型运营平台，而是逐步解决三个问题：

1. 企业可以创建和管理自己的用户。
2. 每个用户有独立余额和独立 API Key。
3. 管理员可以简单地管理用户、余额和 Key。

## 2. 目标用户

- 需要给内部员工统一提供模型 API 的企业
- 需要把国内多个模型接入现有业务系统的开发团队
- 需要按用户区分余额和调用权限的小型 SaaS 团队

## 3. 产品目标范围

当前版本已经提供余额、在线充值、API Key、模型路由和模型调用能力。套餐、订阅和组织等
更完整的商业化能力仍属于后续范围；登录后的可用模型页面以启用的模型路由为准。

### 用户端

- 登录和退出登录
- 查看个人余额
- 查看自己的充值订单、余额流水和调用用量
- 在个人资料复制邀请链接，并通过详情抽屉查看待确认返现、累计收入、邀请人数和最近明细
- 创建、单个删除和批量删除自己的 API Key
- 查看 API 调用格式，以及当前真正可用的模型和个人结算单价
- 查看个人 Key 的创建时间、状态和最近使用时间

### 管理端

- 管理员登录
- 用户列表、搜索和状态筛选
- 创建用户和重置用户密码
- 启用或停用用户
- 查看用户余额
- 手动增加、扣减或调整余额
- 设置全局邀请返现比例，新的充值到账立即使用数据库中的当前比例
- 查看用户 API Key 的前缀、状态和最近使用时间
- 停用存在风险的 API Key

### 模型接入

管理员通过服务端配置的提供商和模型路由维护模型映射；同一对外模型名的启用路由形成轻量
渠道池，按提供商权重排序，并仅对确认发生在连接建立前的失败做有限重试和故障切换。可能已
送达上游的模型 POST 不会自动重放，不提供规则引擎或复杂供应商编排页面。
初始接入目标包括：

- Kimi
- GLM
- DeepSeek

## 4. 明确不做的内容

第一版暂不包含以下功能：

- 套餐、订阅、优惠券和兑换码
- 多支付网关编排、退款工单和复杂财务对账
- 项目级权限和组织层级
- 复杂的计费规则编辑器
- 多级代理商和销售 CRM
- 模型供应商可视化编排后台
- 多区域部署和多服务拆分

## 5. 核心使用流程

### 企业管理员

1. 登录管理员后台。
2. 创建企业用户。
3. 为用户手动设置初始余额，或由用户通过已启用的充值渠道充值。
4. 管理员配置提供商、模型路由和输入/输出单价。
5. 用户创建自己的 API Key。
6. 用户将 Novro API 地址和 Key 配置到业务系统。
7. 管理员根据需要调整余额或停用用户、Key 和模型路由。

### 企业用户

1. 登录 Novro。
2. 选择计费分组，查看该组可用模型和结算单价。
3. 选择计费分组创建 API Key，并在创建成功时复制完整 Key。
4. 使用统一的 OpenAI 或 Anthropic 请求格式接入业务。
5. 在控制台查看余额、充值订单、流水、用量和 Key 状态。

## 6. 产品原则

- 简洁：第一版只保留账号、余额、Key 和调用入口。
- 兼容：尽量兼容现有 OpenAI 和 Anthropic 客户端。
- 可控：所有余额变动保留记录，所有 Key 都可以停用。
- 可扩展：数据库通过 Ent 访问，后续保留切换 PostgreSQL 或 SQLite 的空间。
- 安全：服务端只保存 Key 哈希和必要的前缀，不保存明文 Key。
