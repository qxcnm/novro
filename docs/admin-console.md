# 管理后台

## 当前实现

`/setup` 负责首次管理员初始化，`/register` 提供可配置的普通用户注册，`/login`
支持用户名或邮箱加密码登录，以及可选的第三方 OIDC，`/console` 是普通用户登录后的账号页。
`/admin/users` 提供用户列表、搜索、状态筛选、分页、详情、资料与角色编辑、创建、
启用/停用和密码重置。登录后的控制台使用桌面左侧导航，移动端使用同一导航的左侧
抽屉。页面基于原始 shadcn/ui 原语，支持深色、浅色及系统主题。

源码初始化通过服务端环境设置密码；Docker 一键部署的首次管理员默认为 `novro`，初始化密码必须
由部署管理员通过未入库环境变量提供，首次登录后必须立即重置为新的密码。源码浏览器初始化必须由部署管理员设置高熵
`NOVRO_SETUP_TOKEN`，浏览器提交相同令牌后才能创建第一个管理员；Docker 一键部署直接执行
服务端 `bootstrap-admin`，不开放 `/setup` 引导。数据库使用
唯一安装标记与事务保证该操作只能成功一次；完成后应从部署环境删除令牌。

首次引导创建的 `novro` 是系统管理员，服务端会保护其管理员角色和启用状态，不能被降级或停用。
密码不使用代码中的固定默认值；遗忘密码时由部署管理员临时设置 `NOVRO_ADMIN_PASSWORD`，执行
`novro reset-admin` 后立即清除该环境变量。

OIDC 用户首次登录时可按 `NOVRO_OIDC_AUTO_REGISTER` 自动创建普通成员。系统不会
仅按邮箱合并账号，但本地账号和 OIDC 自动创建账号会共用 `users.email` 字段。管理员可
停用 OIDC 用户，也可以为其设置一个本地恢复密码。

登录后的普通用户菜单展示数据看板、使用日志、可用模型、API Key、API 文档、个人资料和余额流水。
完整 Key 只在创建弹窗中出现一次；个人密钥删除采用不可恢复的撤销并从个人列表移除，管理员审计仍保留记录。管理员额外看到用户、Key 审计、提供商与路由、模型目录、计费分组、请求设置、支付配置、邮件设置和系统公告
入口。提供商页面只显示凭据提示，模型目录和路由只显示单价和映射，不显示密文。

## 交互约定

- 创建用户、重置密码等短表单使用居中弹窗。
- 输入控件不超过 6 个的新增或编辑表单使用居中弹窗；超过 6 个时使用右侧抽屉。
- 停用或启用等需要明确后果的操作使用确认弹窗。
- 用户、API Key、提供商、模型目录、模型路由和计费分组列表支持勾选后批量处理。批量请求复用单条接口的权限与业务校验，服务端拒绝的项目会保留在选择中，便于修正后重试。
- 提供商列表还支持批量同步模型目录；日志、流水和充值订单等只读列表不提供批量变更操作。
- 用户使用批量启用或停用，API Key 使用批量撤销；提供商、模型目录、模型路由和计费分组支持批量软删除。默认计费分组以及仍被 API Key 或模型路由使用的分组不能删除。
- 用户详情和资料编辑使用右侧抽屉，保留列表上下文。
- 桌面控制台保持固定左侧菜单；窄屏通过菜单按钮打开左侧导航抽屉。
- 菜单和页头位于持久布局中；页面切换只替换右侧内容区，不重新加载整套控制台。
- 操作按钮使用 Lucide 图标和可访问名称，表单错误显示在当前弹窗或抽屉内。

## 1. 页面结构

管理后台包含十块核心页面：

1. 用户
2. API Key 审计
3. 提供商与关联模型路由
4. 用户余额与流水（在用户详情抽屉中调整）
5. 模型目录与分维度价格
6. 计费分组与 Key/模型路由倍率
7. 请求生命周期设置
8. 支付配置与充值渠道
9. 注册邮件 SMTP 设置
10. 系统公告

不在第一版加入复杂的统计大屏、供应商编排、套餐、组织、项目或销售管理页面。
个人支付订单在用户余额页只读展示，管理员可在 `/admin/payments` 查看全站充值记录。

## 2. 用户页面

用户列表展示：

- 用户名
- 邮箱
- 显示名称
- 角色
- 状态
- 最近登录时间
- 创建时间

用户操作：

- 创建用户
- 按用户名、邮箱或显示名称搜索，并按状态筛选
- 重置密码
- 启用或停用用户
- 查看用户详情
- 修改显示名称和角色

公开注册、首次初始化和管理员创建本地用户时，用户名、邮箱和密码均为必填项。邮箱统一
转为小写并做唯一校验；已有历史账号可以暂时保留空邮箱，不影响迁移或现有会话。

用户列表的余额图标打开右侧抽屉，管理员可以查看最近流水并填写金额和备注。金额使用
人民币，正数增加、负数扣减；服务端用整数微元校验。真实结算超过预占时会写入补扣流水，
不会把费用截断。余额调整请求必须携带 `Idempotency-Key`；管理页面会为一次编辑生成稳定键，
网络失败后以相同参数重试不会重复加减余额，同键改用其他金额或备注会返回冲突。

## 3. API Key 页面

管理员可以查看所有用户的 Key 元信息，但不能查看完整明文 Key。页面展示：

- Key 名称
- 所属用户
- 计费分组和倍率
- 前缀
- 状态
- 创建时间
- 最近使用时间

管理员可以停用 Key，不能恢复已经撤销的 Key。需要恢复时重新创建。

## 4. 余额调整

余额调整必须填写金额和备注，并自动写入余额流水。页面中明确区分：

- 增加余额
- 扣减余额
- 退款或冲正

调整操作需要记录执行管理员和操作时间。

## 5. 提供商和模型路由

`/admin/providers` 使用“提供商配置”和“关联模型路由配置”两个 Tab。提供商新增和编辑均
使用弹窗维护 HTTP/HTTPS 基础地址、协议、模型获取路径和加密 API Key，不再绑定计费分组。模型获取路径留空时，
OpenAI 兼容和 Anthropic 提供商都使用“基础地址 + `/v1/models`”；第三方平台
可以填写以 `/` 开头的站点绝对路径（例如 `/api/models`）覆盖默认规则。自建或
第三方 OpenAI 兼容网关可以填写公网 HTTP 地址和端口；生产环境优先使用 HTTPS，因为 HTTP
会以明文传输 API Key。新增成功后
立即尝试同步一次上游模型；同步结果会显示检查数量、新建数量和已有数量。同步弹窗只显示这次上游实际返回的模型，不会混入目录中的其他模型；同步失败时也不会回退显示默认模型。模型 ID 在全局目录中只保留一条记录，已有价格不会被另一个提供商覆盖；若上游不支持模型列表，
管理员需要修正模型列表地址后重新同步。同步发现的模型会按精确上游 ID 写入全局目录；
模型同步只创建或恢复候选目录记录，不导入上游返回的价格，也不会自动启用模型；管理员必须在
模型目录定价页维护价格并启用后，才能建立可用路由。关联模型时为每个模型行分别选择启用中的计费分组，再勾选需要建立路由的模型；同一提供商和同一模型可在多个分组中各建立一条路由。批量建立的未知模型路由保持停用。
自动关联不会再拼接提供商代码或数字后缀；迁移会将历史生成的前缀名
归一化回原始上游 ID，并保留管理员手工设置的别名。

管理员可以用相同的对外模型名称创建多条关联路由；同名且协议兼容的启用路由组成渠道池，
网关按提供商权重从高到低选择起始渠道。只有明确发生在取得连接前的连接失败才会有限重试并
依次尝试候选渠道；取得连接、收到 HTTP 响应或结果不明后不会自动重放模型 POST。候选渠道只来自 `billing_group_id` 与当前 API Key 一致的模型路由。权重相同时保持路由的稳定顺序；停用或软删除一条路由只会将该
渠道移出池，不影响同名的其他启用渠道。同一分组中完全相同的对外名称、提供商配置和目录模型不能重复关联。

`/admin/upstream-models` 是独立模型目录。桌面端左侧按目录中的厂商标签动态生成导航和数量，
移动端显示为横向厂商栏；厂商筛选可与模型名称、模型 ID 搜索叠加。目录中的厂商是普通
文本标签，不绑定某一条提供商凭据配置。管理员手动创建模型时填写的六维价格会原子创建为首个
已发布固定价版本；模型资料后续只维护厂商标签、模型 ID 和显示名称。

每个模型行的价格方案入口单独维护 Novro 自定义结算价。固定价方案只有默认六维费率；分时价方案
额外配置 IANA 时区、生效区间，以及星期、开始/结束时间和完整费率窗口。保存草稿不会影响线上，
发布后才进入解析；已发布版本不可编辑，发布新版本会自动关闭前一版本的生效区间。版本记录保留
用于审计，列表展示当前时刻实际生效的价格。历史版本可以通过“切换并发布”直接调整已有版本的生效区间并立即生效；
该操作不复制价格定义、不增加版本号，历史账单仍使用请求发生时保存的费率快照。

当前初始化迁移不再内置固定模型目录；只有真实上游同步返回或管理员手动创建的模型会进入候选目录。
后续上游同步只更新模型的上游名称、显示名称和厂商标签，不导入厂商价格。相同 ID 被多个提供商暴露时
共用同一组 Novro 价格版本，提供商只产生独立的关联路由。上游同步成功后，提供商已不再返回的旧活动
路由会被停用，目录记录和历史调用不会删除；软删除后被上游重新发现的模型和历史路由会恢复。
`/admin/billing-groups` 维护 API Key 和模型路由使用的结算倍率、隐藏属性，并显示每个分组下的授权用户数、Key 数和模型路由数。新增或编辑隐藏分组时，管理员在分组表单中搜索并多选普通成员；B 端组、代理组等隐藏分组各自保存独立名单。管理员自动拥有全部隐藏组权限，用户创建和编辑界面不再提供全局隐藏组开关。撤销某个分组的用户授权后，该用户绑定该组的现有 API Key 会立即停止认证，其他隐藏分组不受影响。历史调用保留当时价格和倍率快照。
停用确认使用确认弹窗。当前没有“测试连接”按钮，避免在没有出口策略时引入任意 URL
探测；真实调用只会从 `/v1` 请求触发，并且网关会阻止内网目标。

## 6. 用户端页面

用户端提供：

- 登录
- 数据看板和只属于当前用户的调用日志；日志支持 API Key、模型、状态和请求 ID 筛选，固定每页 20 条并可查看完整历史
- 可用模型，按用户选择的计费分组、对外名称和协议聚合启用路由，显示渠道数量和所选分组下各候选渠道的最高结算单价
- API Key，创建时选择计费分组，支持复制一次性完整 Key、单个删除和批量删除
- 余额与流水，使用“充值”“最近调用”“余额流水”三个 Tab；调用和流水固定每页 20 条，顶部区分可用余额、当前调用预占和累计已结算费用
- 个人资料中的推荐计划，显示待确认返现、累计收入、邀请人数和可复制邀请链接
- API 文档；公开入口为 `/docs`，登录后的持久控制台入口为 `/console/docs`
- 页头系统公告铃铛；存在启用公告时，每次重新打开控制台自动弹出，站内页面切换不会重复弹出；用户选择“今日关闭”后，当天不再自动弹出，但仍可通过铃铛手动查看，次日按浏览器本地日期恢复；没有公告时显示空状态

## 7. 支付配置页面

`/admin/payments` 使用“充值规则”“易支付”“充值记录”三个 Tab。充值规则维护全局金额
范围、预设金额和按门槛生效的赠送档位；易支付维护接口地址、商户 ID、商户密钥、站点名称、
启用状态，以及可增删改的支付方式。每个支付方式包含显示名称、处理标识、图标、最低充值金额
和启用状态。页面只读展示异步通知地址与支付完成返回地址，并提供复制操作。
系统允许的最低充值金额为 `¥1.00`，管理员可以按实际渠道要求把全局或单个支付方式的最低金额调高。

商户密钥只在服务端以 AES-256-GCM 密文保存，读取接口只返回是否已配置，不会返回密钥内容。
管理员保存后，用户 `/console/billing` 的充值弹窗会按当前启用方式、预设金额和赠送档位实时
更新；停用支付或没有完整配置时，用户端充值按钮保持不可用。充值记录支持按订单、网关流水、
用户、状态和支付方式筛选，同时区分支付金额与实际到账金额。

## 8. 邮件设置页面

`/admin/email` 维护注册验证码邮件使用的 SMTP 主机、端口、加密方式、用户名、发件地址和
密码/访问令牌。页面支持无加密、STARTTLS 和 SSL/TLS，其中正式环境应使用后两者。管理员可
启用或停用邮件发送，并向指定地址发送测试邮件。测试邮件只验证最近保存的配置，不会创建或
消费注册验证码。

SMTP 密码只以 AES-256-GCM 密文保存；读取接口仅返回 `has_password`。密码输入留空会保留
已有凭据。每次验证码发送都会读取当前数据库配置，因此保存和停用都无需重启服务；数据库没有
记录时才回退到 `NOVRO_EMAIL_SMTP_*` 环境变量。

## 9. 推荐设置页面

`/admin/referral` 维护全局邀请返现比例，支持 `0%` 到 `100%`，精确到 `0.01%`。设置保存在
`system_settings.referral_reward_bps`，个人资料的比例与待确认金额、后续充值到账返现都读取
同一数据库值。设为 `0%` 会暂停新的返现；比例调整不重算历史到账奖励。

## 10. 请求设置页面

`/admin/gateway` 维护所有模型端点共用的请求生命周期。SSE 保活默认开启，间隔默认
`15000ms`；网关仅在完整 SSE 事件边界发送注释心跳，不修改上游数据事件。上游总超时覆盖
连接、等待响应头、读取响应体和路由重试，流式空闲超时会在收到任意上游字节后重新计时。
两个上游超时设为 `0` 时关闭。页面还配置输入和输出预占 Token 上限，默认分别为 16384 和
1024；它们只限制余额冻结，最终仍按上游明确 usage 多退少补。设置保存在
`system_settings.gateway_request_settings`，新请求立即读取最新值，进行中的请求保持开始时取得的配置。

## 11. 系统公告页面

`/admin/announcement` 维护一个当前系统公告，包含标题、纯文本正文和启用状态。标题最多 120 个
字符，正文最多 10000 个字符；前端按换行展示并且不解释 HTML。启用公告前标题和正文必须完整。
停用后内容作为草稿保留，但 `/api/account/announcement` 不会把草稿标题或正文下发给普通用户。

用户登录后，页头始终显示有可访问名称的铃铛按钮。已启用公告在每次完整加载控制台后自动弹出
一次，用户可普通关闭并继续工作，也可以通过铃铛重新获取并查看最新内容。选择“今日关闭”时，
前端按当前用户 ID 在浏览器本地保存当天日期，当天后续完整加载不再自动弹出；该操作不隐藏铃铛，
不阻止手动查看，并在浏览器本地日期变化后自动失效。不同用户的关闭状态相互隔离。控制台内部
页面切换保留外壳状态，不重复打断用户；没有启用公告时，铃铛弹窗展示明确的空状态。
